task-runner ext 改造 (extensions/task-runner/index.js):
- 新表 node_runs (run_id, node_id, status, attempts, ms, error,
  started_at, finished_at, PRIMARY KEY(run_id, node_id)) + 索引
- 每节点 INSERT OR REPLACE 落库 — 中间结果可回放
- _activeRuns: Map<run_id, {abort: AbortController, task_id, total}>
  取代旧计数器,每个 run 独立 AbortController,互不影响
- executeNodeWithRetry 注入 Ac 检测:ac?.signal.aborted → lastErr='aborted'
  → 标 canceled 不再重试;同时调 ac.signal.addEventListener('abort') 接
  Promise.race 第二参,abort 瞬间 reject
- executeDag 在每波前查 ac.signal.aborted → 整波中断 + 标 canceled
- _notifyProgress(runId, payload) helper 走 ext.notify('task.run.progress', ...)
  每节点 start/end 各推 1 条 (event: 'start' | 'end' | 'abort')
- task.run.cancel:真取消 — 查 _activeRuns Map → r.abort.abort() →
  invokeExt 立刻 reject('aborted') → node_runs 标 canceled + 推 progress;
  兜底查 runs 表返 current_status
- task.run.active:列活跃 run(task_id / total / run_id)用于 UI 监控
- task.run fire-and-forget 模式现在也返 run_id(B-3 设计漏,补):
  同步建 runId + 注册 Ac + 异步跑 executeDag,这样前端能立刻起 polling
- task.schedule.status: active_runs 字段从原 _activeRuns(计数器,误传)
  修成 _activeRuns.size
