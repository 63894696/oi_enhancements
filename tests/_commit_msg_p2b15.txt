feat(p2.5+15): 三端 config.yaml 化(端口/品牌/论坛 URL)

B-4.F.B ship 后,杂七杂八的硬编码散在三端:
- Python 端 prisIragent_web.py 写死 forum URL
- Electron 壳 main.js 写死 BRAND_UPDATES_URL + brand_max_per_run
- Tauri 壳 lib.rs 写死 BRAND_UPDATES_URL + 24h 周期
- 三端 DEFAULT_WEB_PORT/CALENDAR_PORT 等常量硬编码在 port_config.* 里

本任务统一抽到 prisIrai_config.yaml(仓库根,三端共享)。设计:
  ports.web / companion / music / calendar      — 端口默认(允许 yaml 覆盖)
  brand.url / max_per_run / interval_sec / seen_cap  — 品牌通知
  forum.url / board / hint                       — 论坛 URL

零 PyYAML / js-yaml / serde_yaml 依赖,每端都写极简 regex / 行扫描解析器。

关键设计点
==========
1) yaml 候选路径三端对齐:
   Python:  __file__ 同级 + $INSTDIR + cwd
   JS:      __dirname/.. + $INSTDIR + cwd + __dirname 同级
   Rust:    exe/../prisIrai_config.yaml + exe 上溯 4 级 + $INSTDIR + %APPDATA% + cwd

2) 失败降级:读不到 yaml / 解析失败时,三端都用内置默认值
   (18802 / 18850 / 0 / 18803 / babelspan.com / bbs.babelspan.com 等)
   不抛异常,不破坏既有 port_config 行为。

3) calendar 端口 18803 = web + 1 沿用 P2.5+14 设定;
   日历路由 /prisIragent/calendar + /__calendar_ready 子进程双端口 listen 不变。

4) BRAND 周期默认 86400s = 24h(从 yaml brand.interval_sec),
   Rust 端用 brand_interval_ms() 即时计算,不再写死 24*60*60。

5) forum URL 通过 HTML placeholder + 渲染前 str.replace 注入,
   避免全局修改 _PAGE 常量;降级值走 prisIrai_config 模块默认。
