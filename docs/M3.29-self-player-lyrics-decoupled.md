# M3.29 自实现音乐播放器 + 桌面歌词 + 三进程解耦

> 设计文档 / 验收手册 — 与 memory `prisIr-companion-m29-self-player-2026-09-19.md` 配套

## Context

M3.28 把音乐功能跑通,但**严重依赖 LX Music Desktop**(LX 23330 Open API 主路径 + 用户自己点歌)。
用户原话:

> 当前装了落雪音乐,但是要假设用户设备没有装,所以我们要基于参考落雪音乐的功能,**独立实现 agent 能操作运行的音乐播放器**。

加 M3.28 v2 之后,用户又问「歌词能不能像其它播放器那样跨应用置顶 + 可拖动 + 透明 + 永远最上」—— 这是浏览器窗口内歌词实现不了的(同一页面内 z-index 再高也只在该 webview 内有效,无法盖到 PrisirAI 主面板或浏览器窗口之上)。

**第三个诉求**:陪聊 + 音乐播放器**两个进程解耦**,通过 PrisirAI Tauri 托盘菜单**独立唤起**,各自有独立界面,**不互相绑定**。

## 架构

```
┌──────────────────────────────────────────────────────────────────┐
│ PrisirAI Shell (Tauri 2.11.3 常驻进程,托盘图标)                   │
│  - 启动后端 web @ 18802                                            │
│  - 托盘菜单:打开 PrisirAI / 启动陪聊 / 启动音乐播放器 / 退出      │
│  - 启动音乐播放器:                                                │
│     1. 读 HKCU\Software\PrisirAI\music_port (动态分配)            │
│     2. spawn python prisiragent-music-web.py(独立进程)            │
│     3. 创建 Tauri 透明歌词窗口 → 加载 http://127.0.0.1:{port}/lyrics│
└──────────────────────────────────────────────────────────────────┘
         ↓ spawn                ↓ spawn                ↓ spawn
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ Companion Web   │    │ Music Web        │    │ Lyrics Window   │
│ @ 18850         │    │ @ HKCU 动态端口  │    │ (Tauri Browser  │
│ 陪聊 + M3.27+   │    │ NEW (M3.29)      │    │  Window 透明)   │
└─────────────────┘    └──────────────────┘    └─────────────────┘
```

三进程完全解耦:PrisirAI 壳统一入口,music web 独立 spawn,桌面歌词走 Tauri 第二个 BrowserWindow。

## 关键决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 端口分配 | `bind(0)` OS 自动选 + 写 HKCU | 跨进程可发现,无端口冲突 |
| Lyrics 窗口实现 | Tauri transparent BrowserWindow | 浏览器窗口内 z-index 只能在该 webview 内,跨应用置顶必须 native |
| 自实现播放器 | HTMLAudioElement + `/api/stream/<id>` Range 代理 | 浏览器原生支持,无需 CORS |
| 歌词源 | 本地同名 `.lrc` 优先 + LRCLib.net 兜底 | 离线优先,在 API 限流时不阻塞 |
| 歌词拖动 | `-webkit-app-region: drag` on drag-bar | Tauri `decorations:false` 下唯一原生方案 |
| 配置入口 | 仅 REST + 自然语言意图 | Agent-first,用户无 UI |
| 打包 | PyInstaller → `PrisirAI-music-web.exe` (93.5MB) | 比 PrisirAI 主 exe (397MB) 小,因为不打 litellm/rapidocr |

## Tauri 透明歌词窗配置要点

```json
{
  "label": "lyrics-window",
  "url": "http://127.0.0.1:0/lyrics",
  "transparent": true,
  "decorations": false,
  "alwaysOnTop": true,
  "skipTaskbar": true,
  "resizable": true,
  "visible": false,
  "backgroundColor": "#00000000",
  "width": 720, "height": 180, "minWidth": 320, "minHeight": 120
}
```

`tauri.conf.json` 用 `http://127.0.0.1:0` 占位,实际 URL 由 Rust 端 `open_lyrics_window()` 用 `win.eval("window.location.href = ...")` 注入(端口运行时才能拿到)。

## 跨进程端口共享(关键坑)

```python
# companion/music/port_registry.py
def _write_winreg(port: int) -> bool:
    with winreg.CreateKeyEx(winreg.HKEY_CURRENT_USER, REG_KEY, 0, winreg.KEY_SET_VALUE) as k:
        winreg.SetValueEx(k, REG_VAL, 0, winreg.REG_DWORD, port)  # 必须是 int 不是 str
    return True

def _write_file(port: int, pid: int) -> None:
    payload = {"port": port, "pid": pid, "started_at_ms": int(time.time() * 1000)}
    _FILE_PATH.write_text(json.dumps(payload), encoding="utf-8")
```

**坑1**: `SetValueEx` 第二个参数必须是 `int`,传字符串会导致 REG_SZ 而不是 REG_DWORD,后续读时 `int()` 转换失败。

**坑2**: `read_music_port()` 必须先读文件再读注册表 — 文件有 PID 心跳,可探测进程存活。

**坑3**: companion web 的 `_music_proc` 字段在 kill 自身后会变 None,但 HKCU 仍指向旧 PID,必须双重探测(port + PID)。
**最关键**:必须以端口连通性为最终判据 — `_music_proc.poll()` 在 Windows 上对未 wait 的僵尸进程可能仍返 None。
**坑4(M3.29.7)**: 旧 `Popen` 句柄的 `poll()` 在没 `wait()` 的情况下对死进程仍可能返 None,导致 `_is_alive()` 误判 alive。新版完全以端口连通性为准。

## 风险已规避

| 风险 | 缓解 |
|---|---|
| Tauri 透明 Win10 部分主题不透明 | 加 Win10 兼容回退(透明 false + 高 alpha 背景色)|
| music web 端口冲突 | 启动时 OS 帮选 + 双通道写入 |
| jsdom 启动慢 | music_web 启动时后台预热,首请求稍等 |
| LX Desktop 与自实现并存冲突 | `source=auto` 优先级:LX > self;LX 不可达才落 self |
| 歌词拖动 + alwaysOnTop 抖动 | Tauri `set_focus()` 后 `set_always_on_top(true)`,Win32 顺序稳定 |
| agent 误触发音乐 | nl_intent 加「仅匹配关键词才调」语义;companion system prompt 加「用户没要音乐不要主动调」|
| 三进程状态同步 | SQLite file lock(M3.32 Phase 1 已建 `_prisir_registry/file_changes.jsonl` 模式复用)|
| 音乐文件路径含中文 | Python `PYTHONIOENCODING=utf-8` + pathlib.Path 统一 |
| 火绒杀 `music_web.exe` | PyInstaller 打包后加白名单(沿用 PrisirAI 装机手册)|
| **M3.29.7**: `_music_proc.poll()` 误判 zombie alive | 以端口连通性为唯一最终判据,不依赖 Popen 句柄 |
| **M3.29.7**: 测试 wrapper 读到 HKCU 陈旧端口 | ensure_music_web 三重探测 + 等端口真正可达 |

- **Tauri 透明窗在 Win10 1909 之前不工作**:需 Win10 20H1+(Build 19041+);Win11 没问题
- **音乐 web 首次启动慢**(~2s):jsdom 冷启动 + aiohttp 监听;第二次 0.5s
