# 终局形态：本地轻量壳 + 27B 能力后端（2026-11-01 定调）

> 本文是全仓库增删取舍的准绳。任何组件，先回答"它属于哪一层"，答不上来的就该砍。

---

## 一、定调

**本地只留壳，能力全部沉到后端，后端跑在 27B 的运行环境里。**

两者用同一套契约通信，因此：

- 云端有 27B → 能力全开
- 本地只有小模型 / 断网 → **同一份壳、同一套契约**，降级而不变形
- 用户感知是"一个 agent"，不是一个本地软件 + 一个云服务

## 二、三层职责

| 层 | 职责 | 为什么不能搬走 | 现有资产 |
|---|---|---|---|
| **壳（本地）** | 触达 + 首响应 + 边界 | 云端摸不到窗口句柄、光标、输入法、剪贴板、未上传文件；光标级反馈要 <100ms | `prisiragent-shell`(Electron) / `agent_shell`(orb) / `prisIragent_ime` / 扩展里的本地工具 |
| **契约（两端共有）** | 会话、工单、事件、能力声明 | 云地同源的唯一保证 | 待建：`asr/tts provider`、`focus context`、报告六态 |
| **脑（27B）** | 规划、研判、编排、长任务 | 本地跑不动，也不需要跑 | `fastlane`(路由) + 27B 推理环境 |

## 三、和 Cursor 的差别在哪

Cursor 是「代码编辑器里的 agent」：它的世界是仓库，入口是编辑器，产出是 diff。

我们要做的是「**整台机器上的 agent**」：

| 维度 | Cursor | Prisir（目标） |
|---|---|---|
| 作用域 | 一个 repo | 整机：文件 / 窗口 / 输入法 / 屏幕 / 日历 / 自托管服务 |
| 入口 | 编辑器内 | 指针级：orb、输入法 AI 键、悬停、语音 |
| 产出 | diff | 动作 + 结果 + 可回看的工单 |
| 触发 | 人提问 | 人提问 **或** 规则允许时自主（工单模型） |
| 本地角色 | 客户端 | 客户端 + **唯一能触达机器的手** |

**差异点不在模型，在"手"和"入口"。** 27B 负责想，本地负责碰得到。

## 四、这条准绳怎么用

新增任何东西之前，问三个问题：

1. **它属于哪一层？** 答不上来 → 不做
2. **如果它是壳，云端能不能替它做？** 能 → 不该在壳里
3. **如果它是脑，本地降级时有没有兜底？** 没有 → 补契约

用它回看已经做过的事：

| 对象 | 归属 | 判定 |
|---|---|---|
| 25 个 bridge-status | 壳（触达自托管服务） | 属于壳，但**形态错了**——应 1 个运行时 + N 条配置 |
| 20 个本地工具 | 壳（触达本机） | ✅ 正确，是护城河 |
| 6 个 promo | 壳（给脑查资料） | ✅ 正确，但应合并成 1 个 `api-catalog` |
| `voice_input` 三进程 | 脑 + 壳混合 | ❌ 切错了，语音应拆成 provider + 壳内 channel |
| `companion` 独立服务 | 壳 + 脑混合 | ❌ 应并入主壳成为"语音模式" |
| `prisiragent-tauri` | 壳（第二套） | ❌ 重复，已放弃 |
| `fastlane` | 脑 | ✅ 正确，继续做薄 |

## 五、对当前工作的约束

1. **不在壳里放模型**。壳只做 I/O、状态、渲染、触达。
2. **所有能力必须能被契约描述**。写不出契约的能力，就是没想清楚。
3. **降级路径是必需品，不是可选项**。每个云端能力都要有不联网时的行为定义。
4. **IME 属于壳，而且是"指针级入口"的核心**——它比聊天窗更接近用户注意力。
