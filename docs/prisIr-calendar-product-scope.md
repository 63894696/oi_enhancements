# Prisir 日历 — 产品边界声明

> 状态: v1.0 · 适用 PrisirAI 旅行助手首发版
> 受众: 用户文档 / 客服 / 销售口径 · 不是开发契约
> 关联: `travel-time-buddy.md`(9 条行为契约,实现侧)

---

## 1. 一句话定位

**PrisirAI 旅行助手不是日历 App,是你的日程大脑。** 你说去哪、做什么,agent 替你把通勤时间和日程冲突都管好;你只管看时间线,不用动手设置。

---

## 2. 我们做什么 / 不做什么

| 我们做 | 我们不做 |
|---|---|
| agent 听完你说的话,自动算通勤并插入交通 buffer | 替代 Google Calendar 的拖拽、改色、循环事件 |
| dismiss ledger —— 你删一次,policy 记住,下次不再犯 | 同步 iCloud / Google Calendar / Outlook(任何云日历) |
| 一键导出 ICS 供你备份或导入系统日历 | 双向 sync —— 系统日历里改了,PrisirAI 看不见 |
| 时间线只读视图,事件来源可追溯到对话原话 | 提供日历设置页、主题色、提醒音、视图切换 |
| Maps ETA 接高德 / Google 双 vendor,按 IP 地区路由 | 用户手动查路线再粘回对话 |
| 首次会话一次性申请位置/网络权限,之后静默调用 | 每次行程前弹权限确认 |
| 链式日程自动识别(A → B → C 衔接),冲突时主动提议改时 | 让你自己拖卡片解决冲突 |

---

## 3. 典型对话流剧本

### 场景 A: 用户开口,agent 接住

> 用户: "我明天下午 3 点去国贸 SK 见客户。"

PrisirAI 不会问"你想加交通时间吗?加多少分钟?"。它会回:

> agent: "好的。明天下午 3 点国贸 SK,我会查从你常去的 workplace 到国贸 SK 的驾车时长,加 15 分钟前置缓冲。如果你住址不同告诉我。"

用户一句回复,日程就成型。无设置,无配置,无拖拽。

### 场景 B: 用户看时间线,可能好奇"这什么"

用户打开 Prisir 日历,看到:

```
14:45 — 15:00  交通 · 国贸 SK(驾车,高德,约 12 km)
15:00 — 16:00  会议 · 国贸 SK · 张总
```

用户感觉"诶,这条 14:45 的卡是什么?" → 点卡片 → 弹出说明:

> 自动插入 · 来自你 9/19 11:42 的对话 "明天下午 3 点去国贸 SK"
> 通勤估算: 高德驾车 12 分钟 + 15 分钟前置缓冲
> 来源: Maps ETA · 高德 · 2026-09-19 14:30 拉取

### 场景 C: 用户嫌 buffer 长,甩手 X 一下

用户觉得 15 分钟太长(老司机,这条路闭着眼开),在 14:45 的交通卡上点 **X**(dismiss)。

> agent: "好,我记下了:workplace → 国贸 SK 这条路不再自动加前置 buffer。下次你说'国贸 SK'我就直接订 3 点。"

不需要去设置里关开关,不需要写配置文件。dismiss ledger 自动沉淀这条 policy,后续对话直接生效。

## 4. 与 Google Calendar / Outlook 的边界声明

**我们只服务一种用户**:愿意把日程的"维护权"交给 agent 的人。

| 你需要的 | 我们的方案 | Google / Outlook |
|---|---|---|
| agent 主动算通勤、避免迟到 | ✅ 核心能力 | ❌ 你自己拖 |
| 多端实时同步(手机 ↔ 电脑 ↔ 网页) | ❌ 不做 | ✅ 核心能力 |
| 多人协作日历 / 共享给同事 | ❌ 不做 | ✅ 核心能力 |
| 数据留在本机,不上云 | ✅ 默认行为 | ❌ 上云是默认 |
| 自定义语义(dismiss = policy)| ✅ 设计一等公民 | ❌ 改事件属性 = 设置迷宫 |

**结论**: 如果你已经重度依赖 Google Calendar 跨设备同步、或团队 8 个人共用一个会议室日历 —— PrisirAI 不是你的选择,**不要来**。我们不会假装未来会支持,那不是这一代产品的目标。

我们给的是:agent 主动服务 + 数据本地化 + 你能用自然语言塑造日程行为。
我们不给的是:跨设备实时同步。

## 5. ICS 导出的诚实说明

PrisirAI 提供的 ICS 导出,**是单向备份,不是双向 sync**。

具体含义:

- ✅ 你可以一键导出 ICS 文件,导入系统日历(Outlook / Apple 日历 / 手机自带日历)
- ✅ 系统日历会显示所有事件,包括 agent 插入的交通 buffer
- ❌ **你在系统日历里编辑、删除、移动 buffer,PrisirAI 不知道**
- ❌ 系统日历里新建的事件不会回流到 PrisirAI
- ❌ 重导 ICS 会用 PrisirAI 的当前快照**覆盖**你之前在系统日历的本地修改(假设你再次走"导入"流程)

**这是有意的产品决策,不是 bug。** 双向 sync 需要常驻连接、冲突解决、并发控制 —— 会让"日程大脑"变成"日程 App",违背产品定位。我们不做。

如果用户只是想要"看一眼今天的安排",系统日历的 ICS 订阅已经够用;如果用户想要"在手机上也能让 agent 改我的行程",对不起,本代产品做不到。

## 6. 失败模式文档

下面这些场景,**PrisirAI 帮不上忙**。我们写出来不是为了承诺"以后会修",是为了让你买之前知道边界。

| 场景 | PrisirAI 的表现 | 原因 |
|---|---|---|
| 换了电脑,新机器装 PrisirAI | 日历是空的 | 没跨设备 sync |
| 删了一条 buffer,想从备份找回 | 备份 ICS 里也没有 | 单向导出,删了就是删了 |
| 手机想看今天行程 | 必须手动从 PrisirAI 导出 ICS 拷过去,再导入手机日历 | 没自动同步,没推送 |
| 想跟同事共享一个日历视图 | 做不到 | 没共享/协作功能 |
| 想收到"会议前 10 分钟弹窗提醒" | 看系统日历(如果导入了 ICS)| PrisirAI 不在系统层驻留 |
| 想让 Siri / 小爱同学读出今天的行程 | 看系统日历的朗读集成 | PrisirAI 不接系统语音 |
| 跨时区出差(北京飞东京) | agent 能算,但 ETA 用本机时间,不会自动切时区显示 | v1.0 不做时区切换,自动 fallback 到本机时区 |

**这是自研日程大脑的代价,不是设计缺陷。**

我们的赌注是:愿意为"agent 主动管日程"付出"跨设备 sync"这个能力的人,在你的使用场景里,只在一台主设备上过日子(笔记本 or 台式机,二选一)。如果你的日程需要随时在手机、平板、网页、车载系统之间流动 —— 请用 Google Calendar 或 Outlook,我们尊重你的选择。

## 写在最后

PrisirAI 旅行助手是为这样一群人做的:

> 愿意把日程的"维护权"交给 agent,主力只用一台设备,不在意跨端同步,把"少操心"看得比"多设备"更值钱。

不是为所有人做的,也不打算变成所有人需要的。
