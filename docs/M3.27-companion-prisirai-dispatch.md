# M3.27 — 陪聊 ↔ PrisirAI 派发联动(2026-09-18 设计稿)

## Context

### 用户原话(2026-09-18)
「结合灵犀拼音输入法中灵犀语音的设计,思考怎样可以与 PrisirAI 的执行能力联动 ——
陪聊做的轻量化,重点实现语音实时交流;重量执行操作的活,交给整合了更多专业功能的 PrisirAI。
灵犀语音在讲述完输入内容完成文字上屏时,还会把文字在自己的缓存区保留。
那么陪聊可以学习这个文字内容缓存(保留上下文),然后在用户明确要把前面聊的内容在 PrisirAI 中做任务推进时,
调用这个谈话内容的文字缓存输出到 PrisirAI 的对话框,
这样既保证指令清晰也能让用户看完确认,自行决定要不要修改还是直接自己点发送。」

### 已确认的 4 个倾向

| 维度 | 方案 |
|---|---|
| A 触发 | 触发词「交给 PrisirAI」+ 顶栏 UI 按钮并存(语音主路径,按钮兜底) |
| B 缓存策略 | **保留全部**对话 + **增量派发**(陪聊记「上次派发到了第几条」,派发 #2 起只送新增) |
| C 写入姿势 | **HTTP 显式接口** `POST /prisiragent/api/external_inject`(companion → prisiragent_web,跨进程 HTTP)— **不自动 send** |
| D 回路 | 派发后陪聊**仍可对话**,但视觉提示「已派发 #N 给 PrisirAI」(N = 派发次数) |

### 调研结果(2026-09-18)

- **PrisirAI 现有 HTTP**:走 `BaseHTTPRequestHandler + ThreadingHTTPServer`(std lib,不是 aiohttp);单端点分发 `do_POST(self.path)` → `path == "/prisiragent/api/xxx"` 模式(`prisiragent_web.py:9613`)
- **PrisirAI 推送通道**:不是 WebSocket — 走 **SSE**(`_sse_broadcast` at line 2760,`_SSE_QUEUES` 模块级)+ **`/api/status` 轮询**(前端 `pollResult()` line 5833,900ms)
- **后端**:`do_POST` 用 `self._json(data, code=...)`;`do_GET` 用 `parse_qs`,取参句式 `(qs.get("x") or [""])[0]`;`_read_body()` 已封装 JSON 解码
- **前端**:无 ws onmessage / case 分支;注入交互**必须新加 SSE 订阅 + 渲染逻辑**(或在 inject-flash 定时器里 poll)
- **新建 `_INJECT_QUEUE` 模块级 list + threading.Lock**(FIFO 32),push 后调 `_sse_broadcast({"type": "external_inject", ...})`
- **PrisirAI 主输入框**:HTML `<textarea id="input">` + `<button id="send" onclick="sendMessage()">`(`prisiragent_web.py:4260, 4272, 5734`)
- **companion 现有耦合**:跟 prisiragent_web 完全独立(不依赖其 URL,不共享 session),通过 `PRISIR_DATA_DIR` 共享 SQLite 知识库(fcontent.db)
- **companion 配置入口**:已经在 M3.24 settings 面板里加 `.m323-section`,沿用即可

→ 不需要新架 IPC/共享内存,companion HTTP POST → PrisirAI → 队列 → 前端 ws 推送 → 填入 `#input`。

## 总体架构

```
┌────────────────────┐        POST /api/external_inject        ┌────────────────────────┐
│  companion 陪聊壳  │ ───────────────────────────────────────→ │  prisiragent_web       │
│  (port 18850)      │                                          │  (port 18800)          │
│                    │                                          │                        │
│  - 文字缓存 buffer │                                          │  - inject queue        │
│  - 增量 cursor     │                                          │  - ws push to front    │
│  - 触发词检测      │                                          │  - 前端 ws handler     │
│  - 顶栏「📤」按钮  │                                          │    把 queue 内容填     │
│                    │                                          │    进 #input (不 send) │
└────────────────────┘                                          └────────────────────────┘
```

### 三段式数据流

1. **companion 缓存**(每通陪聊 = 每个 sid 一个 buffer)
   - 持续追加 user turn + assistant turn
   - 维护 `dispatch_cursor` 指针(已派发到的 turn index)
2. **派发触发** → 取 buffer[cursor:] → POST 到 PrisirAI
3. **PrisirAI 接收** → push 到 `_inject_queue`(FIFO)→ **`_sse_broadcast({type:"external_inject", text, id})`** → 前端 EventSource handler 填 `#input.value`

  ```python
  _INJECT_QUEUE: list = []            # FIFO,maxsize=32,溢出 drop 老
  _INJECT_LOCK = threading.Lock()
  _INJECT_MAX = 32
  ```
- **`/prisiragent/api/external_inject`(POST,在 do_POST 现有 if/elif 链中加分支,靠近 line 9624)**:
  ```python
  elif path == "/prisiragent/api/external_inject":
      text = (body.get("text") or "").strip()
      if not text:
          self._json({"ok": False, "err": "text 必填"}, 400)
          return
      item = {
          "id": uuid.uuid4().hex[:8],
          "ts": time.time(),
          "text": text,
          "source": body.get("source", "external"),
          "sid": body.get("sid", ""),
      }
      with _INJECT_LOCK:
          _INJECT_QUEUE.append(item)
          if len(_INJECT_QUEUE) > _INJECT_MAX:
              _INJECT_QUEUE.pop(0)
      try:
          _sse_broadcast({"type": "external_inject", **item})
      except Exception:
          pass  # SSE 失败不影响主流程
      self._json({"ok": True, "id": item["id"], "queue_size": len(_INJECT_QUEUE)})
  ```
- **`/prisiragent/api/external_inject/peek`(GET,在 do_GET 现有 elif 链加)**:

  ```python
  elif path == "/prisiragent/api/external_inject/peek":
  ```

  ```js
      const es = new EventSource("/prisiragent/api/events");  // 看是否已有 SSE 端点
  ```

## 边界 / 隐私

- **不在派发内容里包含**:
  - 知识库命中 hits 列表(含 path/snippet — 暴露用户文件路径)
  - 屏幕 a11y 内容(用户当前在做什么 — 隐私)
- **派发的内容**:仅 user text + assistant text,无 metadata
- **companion → PrisirAI 跨进程 HTTP**:走 127.0.0.1,**不出本机**(PrisirAI 没有公网端口)
- **可关闭**:M3.24 settings 加 toggle「允许派发到 PrisirAI」(默认开)→ 关闭后 `/api/dispatch` 返 403

## 不做的事

- ❌ 不做自动 send(明确的人在回路 — 用户看完再决定)
- ❌ 不让 companion 直接读 PrisirAI 内部状态(只走显式接口)
- ❌ 不在派发 body 里塞 hit/a11y 元数据(隐私 + 用户可控)
- ❌ 不做派发历史回看(留给 M3.28+)
- ❌ 不做跨平台(linux/macOS 本期不验;接口定义一致就行)
- ❌ 不做派发失败重试队列(用户手动再触发即可)

## 风险

| 风险 | 缓解 |
|---|---|
| 用户正在打字时被 inject 抢断 | toast 提示「已填入输入框(可编辑)」+ 高亮 + scroll 到末尾,简单不抢 |
| PrisirAI 不在线 | companion /api/dispatch 返 502 + UI 红字提示「PrisirAI 未启动」 |
| 派发内容太长撑爆 input | companion 端裁 8000 字 + 写「[已截断]」标记 |
| queue 后端到队列满 | 32 条上限,FIFO drop 老 + ack 后从队列移除(常态不会满) |
| 触发词误命中("交给 PrisirAI 的朋友"…)| 严格匹配词列表,不含子串;先弹确认卡,用户二次确认才真派 |
| ws 断线导致 inject 不广播 | GET /peek 兜底(前端每 3s 拉一次) |
| 跨进程依赖(companion 启动时 PrisirAI 没起) | lazy connect,POST 时才连 + 错返 502 |
| 同一台机器端口冲突 | 配置项 `prisirai_url`,默认 127.0.0.1:18800,可在 settings 改 |
