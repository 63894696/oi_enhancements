# gh CLI 通用 fetcher + search provider — PrisirAI 信息获取能力增强(P3j T21-C)

## Context

[GitHub CLI](https://cli.github.com)(gh)是 Agent-Reach 的上游工具之一(用于
`github` 平台)。**PrisirAI 之前没直接调 gh,GitHub 内容只能通过 jina/feedparser
抓 HTML(经常风控 403)**。

gh 2.96.0 已装在 `C:\Program Files\GitHub CLI\gh.exe`(auth 已登录),
**用户原话**:「请将其上游工具逐一集成」。

| 能力 | PrisirAI 原(走 jina/html) | gh CLI 直接调 |
|------|---------------------------|----------------|
| 仓库元数据(stars/forks/desc) | HTML 解析(易风控) | gh api `repos/owner/name`(结构化 JSON) |
| Issue / PR 读 | HTML 解析(标签/作者散落) | gh api `repos/.../issues/N`(含 is_pull_request) |
| GitHub 搜索 | ❌ 没接 | gh search(repos/issues/prs/code) |
| auth 探测 | ❌ | gh auth status(给 UI 灯看) |

### 设计要点

- **gh --jq 过滤字段**:`repo_info/issue_get/pr_get` 走 `--jq` 只取必要字段,
  减小 stdout + 防 100KB+ 大 JSON 卡住
- **search --json 字段细分**:repos / issues / prs / code 支持的字段不同
  (gh 2.96 实测:repos 没 `title` 字段),按 kind 用不同字段白名单
- **失败一律不 raise**:subprocess.run 全部 try/except + returncode 校验
- **auth 状态暴露**:`gh_health.auth_status = logged_in / not_logged_in`,
  给 UI 灯看(private repo 才需登录)
- **github.com URL 路由**:`/owner/repo` → repo_info;`/owner/repo/issues/N` →
  issue_get;`/owner/repo/pull/N` → issue_get(gh api 同端点);其他 3+ 段
  → error=unsupported_github_url
- **gh_search provider lazy 注册**:只在 `shutil.which("gh")` 命中时注册

### picker 优先级(github.com URL)

```
jina(任意 URL markdown,可能受 403)
→ feedparser(URL 启发式)
→ ytdlp_meta(视频类 URL)
→ gh_api(github.com URL 结构化数据)  ← 新增,本次
→ first-wins 兜底(http_urllib / a11y / browser_use_cli)
```

`gh_api` 不在显式优先级循环里(由 first-wins 兜底取),因为 github.com URL
场景有限,只在显式 web_fetch.fetch 时由 gh_api 自然命中。

### gh_search provider(整合到 web_search.merge)

```
web_search.search(query, limit)
  → 同时跑:ddg_html + baidu + bing_public + (tavily/serper 可选) +
            jina_search(若 env) + gh_search(若 gh 装)
  → RRF rank fusion 合并
```

主对话说「搜 GitHub 上 anthropic-sdk-python 仓库」→ gh_search 命中 →
LLM 看到 `https://github.com/anthropics/anthropic-sdk-python` 列表 →
可直接调 web.gh.repo 拿详情。

### 与 agent-reach 的关系

- **agent-reach `read github`**:走 Playwright + 鉴权(支持 private 仓库)
- **gh_bridge**:调 gh api(public 仓库免 token)
- **互补不冲突**:public 仓库走 gh(更快 + 结构化),private 仓库走 agent-reach

## 数据流

```
主对话「github.com/anthropics/anthropic-sdk-python 多少 stars」
  ↓ LLM 解析出 [[EXEC: web.gh.repo owner="anthropics" name="anthropic-sdk-python"]]
  ↓ scan_and_exec (T16-A)
  ↓ endpoints._web_gh_repo
  ↓ gh_bridge.repo_info
  ↓ subprocess: gh api repos/anthropics/anthropic-sdk-python --jq "..."
  ↓ {ok, repo: {stargazers_count: 3922, ...}}
  ↓ build_exec_result(ok=True, ...)
  ↓ ws event + 前端渲染

主对话「搜 GitHub 仓库 anthropic-sdk-python」
  ↓ [[EXEC: web.gh.search query="anthropic-sdk-python" kind="repos"]]
  ↓ gh_bridge.search → gh search repos "..." --limit 10 --json
  ↓ [{name, url, description}, ...]
  ↓ web_search.merge 或前端直接展示

web_fetch.fetch("https://github.com/anthropics/anthropic-sdk-python")
  └─ 并发跑:http_urllib + jina + feedparser + ytdlp_meta + gh_api
  └─ picker 第一遍 jina;若 jina 拿不到 / 403 → 落 gh_api(github.com URL 专属)
  └─ 缓存到 7d 磁盘 + 32 条内存 LRU
```

## 易踩坑

1. **gh search `--json` 字段按 kind 不同**:repos 没有 title;issues/prs 才有;
   code 字段更少。必须按 kind 分开字段白名单,不然 gh 返
   `Unknown JSON field: "title"` 直接挂。
2. **gh auth 已登录但未测过**:`gh_health` 会顺带 `gh auth status` 探测,
   `auth_status` 给 UI 灯看;private repo 才需登录
3. **gh API 60 req/h 匿名限流**:github.com 公开仓库走 gh api 也算 60/h
   (unauthenticated),长期跑要 `gh auth login` 升 5000/h
4. **GitHub 不识别 3 段 URL**:如 `github.com/settings/profile/edit` 走
   unsupported 路径,error=unsupported_github_url
5. **测试 mock `_run`**:gh_bridge._run 是内部函数,monkeypatch
   `"prisir_work.gh_bridge._run"` 全局属性
6. **gh_api provider import 路径**:provider 内部 `from prisir_work import gh_bridge`,
   monkeypatch 同一模块级属性即可
7. **测试触发 fetcher lazy register**:`web_fetch._FETCHERS` 在第一次
   `fetch()` 调用时才注册;测试需要 try-fetch 一次触发
8. **gh 不在 PATH**:`gh_search` provider 自动跳过注册,
   `gh_health.installed=False`;verify check 也会跳过 gh_search 检查
