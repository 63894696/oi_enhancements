# M3.28 — 滚动歌单:落雪 source 协议直接接入(2026-09-18 设计稿)

## Context

### 用户原话(2026-09-18)
「当前的落雪音乐即使填入了这么多源,但实际使用时只能用一个,如果遇到歌单中某一首歌该源没有会无法播放,需要手动更改源尝试,所以我想如果这些源我们自己能调,能否做小工具用**模型梯队概念自动换源,自动换歌单**,**只要播放就一直多歌单多源滚动下去**,用户只要轻松决定选上一首、下一首、暂停、播放/停止即可,最多再考虑要不要加显示歌词。如果源失效用户也能让 agent 帮忙找然后自动配置,完全不需要用户手动操作。」

### 用户后续决策(2026-09-18 二轮)
1. **Phase 1+2 先出** —— 验证 jsdom shim 真能跑通 10 source(关键 PoC),验真后再做 Phase 3+4
2. **歌词要做** —— 受好评的方案做参考,但**只做歌词显示 UI,不做设置页面**(歌词时延/字号/颜色这些由 agent 通过自然语言控制)

4. **新增 juhe 源** —— `pdone/lx-music-source/main/juhe/latest.js`(11 个 source)

### Agent-first 思路(2026-09-18 三轮,跟 browser_action 同模式)
「现在有给 agent 操作的浏览器,以同样的思路做给 agent 操作的音乐播放器。调研一下播放器项目,看是否有可以复用的思路。」

**核心思想**:**不替用户手动操作,而是给 agent 一个受控接口**(权限闸 + 自然语言意图)。和 `prisIr-browser-action-playwright.md` 的设计同源。

### 调研结论(2026-09-18)

#### 主流播放器架构对比

| 项目 | 类型 | Plugin 系统 | Agent 友好度 | 可复用点 |
|---|---|---|---|---|
| **lx-music-desktop** (lyswhut) | Electron + Vue + Pinia | `globalThis.lx` + `EVENT_NAMES.request` 监听器 | 中(我们已在用) | source plugin 协议 → jsdom shim |
| **YesPlayMusic** (qier222) | Electron + Vue 3 | `ipcMain.handle` + 原生 plugin | 低(Electron 绑死) | — |
| **MusicFree** (maotoumao) | **纯插件宿主**(无内置源) | `IPluginDefine` commonjs 模块 + `Function` 沙箱 | **高** | **直接抄 schema + 沙箱** |
| **Spotify MCP Server** | Python FastMCP | Spotify Web API | 中 | **tool schema 命名习惯** |
| **Audio Player MCP** | Python FastMCP | 本地文件目录 | 中 | `play_audio` / `stop_playback` 三方法 |
| **MPRIS (D-Bus)** | Linux 标准 | — | 高(Linux 桌面标准) | MediaSession API 等价思路 |
| **Plexamp / Nuclear** | Electron/NW.js | — | 低 | — |

#### 关键发现:MusicFree 是 LX Music 的继任者/超集

**MusicFree 的 plugin 协议**(`src/types/plugin.d.ts`) —— 15 个核心方法,**最小只需要 3 个**:
- `search(query, page, type)` — 搜索
- `getMediaSource(musicItem, quality)` — 拿直链(对位 LX `musicUrl`)
- `getLyric(musicItem)` — 拿歌词(对位 LX `lyric`)

**对比 LX Music source**:
- LX: `EVENT_NAMES.request` 事件,action ∈ {musicUrl, search, lyric}
- MusicFree: 直接 async method,更 OO

**我们采纳的策略**:**Phase 1 沿用 LX 协议**(jsdom 跑现有 11 source),Phase 2+ 抽象出「LX protocol adapter → MusicFree-style API」中间层,未来可加 MusicFree 插件源(它们生态更大)。

#### 调研启发的设计决定

| 维度 | 决定 | 出处 |
|---|---|---|
| **Tool schema 命名** | 用 `play_song` / `pause_playback` / `next_track`(不是 `music_play`)| Spotify MCP / Audio Player MCP 命名习惯,LLM 训练数据更熟 |
| **Plugin 沙箱** | Phase 1 用 jsdom;Phase 2+ 包一层 `Function` 沙箱 | MusicFree 用 `Function` constructor + 白名单 axios/cheerio/dayjs |
| **Plugin 元数据缓存** | MMKV-style diskcache,7d TTL | MusicFree 用 MMKV |
| **userVariables** | Phase 2+ 加(sixyin / changqing 可能需要) | MusicFree `userVariables` 字段 |
| **supportedMethods 过滤** | source 注册时声明 methods;查询时跳过无 lyric 的 source | MusicFree `getPluginsWithAbility` |
| **不抄** | 不暴露 MCP server(我们是内置 FC);不做 Android/iOS;不做付费音质 |

### 调研结果(2026-09-18)

**LX Music source 协议关键事实**:
- 不是简单 mp3 URL,每个 source 是 **LX Music Desktop 专用 `.js` 插件**,通过 `globalThis.lx` runtime 与主进程通讯
- 核心 API:`on(EVENT_NAMES.request, ({source, action, info}) => Promise)` 处理 `musicUrl` / `search` / `lyric` 三种 action
- `source` 是平台代号(kw=网易/wy=QQ/kg=酷狗/tx=腾讯/mg=咪咕)
- 通过 `send(EVENT_NAMES.inited, {sources})` 自报支持平台 + quality
- **已实测**:`ikun` / `huibq` 等自带独立 HTTP API;`sixyin` / `lx_main` 内嵌混淆 + 自建 API
- **关键发现**:这 10 个 source 都没有调用 `lxUtils.crypto.aesEncrypt`(2023 之后 LX 简化了),**只用到 request + on + send + currentScriptInfo 4 个函数 + 部分 md5**

**实测连通性**:
- `ikun api.ikunshare.com` → 连接超时(海外 API 不稳)
- `huibq lxmusicapi.onrender.com` → 503 服务挂了
- 其余需要「LX runtime + jsdom」才能跑 → 但 **shim 复杂度可控**

### 滚动歌单核心算法

```python
class RollingPlaylist:
    def __init__(self):
        self.queue: deque[Track] = deque(maxlen=200)  # 滑动窗口
        self.sources: list[Source] = [ikun, huibq, flower, ...]
        self.now_playing: Track | None = None
        self.seeds: deque[Track] = deque(maxlen=20)   # 用户点的歌作为种子
        self.agent_opinions: list[str] = []            # agent 自然语言意见

    async def next_track(self):
        """循环直到拿到能播的下一首"""
        for _ in range(3 * len(self.sources)):  # 3 轮梯队
            if not self.queue:
                await self._refill_queue()
            candidate = self.queue.popleft()
            for src in self.sources:
                try:
                    url = await src.music_url(candidate, quality="320k")
                    if url and url.startswith("http"):
                        self.now_playing = candidate
                        return url
                except Exception as e:
                    log.warning(f"[{src.name}] {candidate.title} 失败: {e}")
                    continue
            log.info(f"{candidate.title} 所有源失败,跳过")
        raise AllSourcesFailed("滚动歌单连续失败")

    async def _refill_queue(self):
        """推荐池混合策略(2026-09-18 用户决策):
        1. 用户点的歌为种子,优先推相似风格
        2. 播完种子滚动,从公开榜单拉相似曲
        3. agent 自然语言意见作为过滤(「别太吵」「90 年代」「摇滚别要」)
        """
        candidates = []
        if self.seeds:
            # 种子驱动:用最近 1 个种子的 artist/album 推相似
            last_seed = self.seeds[-1]
            candidates += await recommend_pool.similar_to(last_seed, n=30)
        # 滚动填充:公开榜单随机
        candidates += await recommend_pool.random_top(n=30,
            filter=self.agent_opinions)  # 应用意见过滤
        random.shuffle(candidates)
        self.queue.extend(candidates)
```

#### A1. 入口 `lx_runtime.js`
```javascript
// 1. 启动 jsdom 提供 window + globalThis.lx 桩
const { JSDOM } = require("jsdom");
const dom = new JSDOM("<!DOCTYPE html>");
const win = dom.window;

const { EventEmitter } = require("events");
const bus = new EventEmitter();

// 2. axios shim
const axios = require("axios");

// 3. globalThis.lx 注入
win.lx = {
    EVENT_NAMES: {
        request: "request",
        inited: "inited",
        updateAlert: "updateAlert",
    },
    request: (url, options, cb) => {
        const method = (options.method || "GET").toLowerCase();
        const start = Date.now();
        axios({
            url, method,
            headers: options.headers || {},
            timeout: (options.timeout || 8000),
            maxRedirects: 5,
        })
        .then(resp => cb(null, { statusCode: resp.status, body: resp.data, headers: resp.headers }))
        .catch(err => cb(err, null));
    },
    on: (event, handler) => bus.on(event, handler),
    send: (event, data) => bus.emit(event, data),
    utils: {
        buffer: { from: (s) => Buffer.from(s), bufToString: (b) => b.toString() },
        crypto: {
            aesEncrypt: (text, key, iv, mode) => require("./crypto_aes").aesEncrypt(text, key, iv, mode),
            md5: (s) => require("crypto").createHash("md5").update(s).digest("hex"),
            randomBytes: (n) => require("crypto").randomBytes(n).toString("hex"),
        },
    },
    version: "M3.28-shim",
    env: "mobile",  // 多数 source 在 mobile 分支更简单
};

// 4. 加载所有 source .js (启动时一次性)
const sourceFiles = [
    "/lx-music-source.js", "/changqing.js", "/huanyin.js",
    "/ikun.js", "/flower.js", "/grass.js",
    "/huibq.js", "/lx.js", "/qdy.js", "/sixyin.js",
];
for (const path of sourceFiles) {
    try {
        const code = fs.readFileSync(path, "utf8");
        // 提供 currentScriptInfo.rawScript
        win.currentScriptInfo = { rawScript: code };
        win.eval(code);
        log(`[lx_runtime] loaded ${path}`);
    } catch (e) {
        log(`[lx_runtime] ${path} load failed: ${e.message}`);
    }
}

// 5. 监听 inited 事件收集 source 元数据
const sources = {};
bus.on("inited", (data) => {
    Object.assign(sources, data.sources || {});
});

// 6. 暴露 HTTP RPC 给 Python (走 unix socket / stdio)
process.stdin.on("data", async (buf) => {
    const req = JSON.parse(buf.toString());
    const { id, action, source, info } = req;
    try {
        let handler;
        bus.emit("request", { source, action, info }, (result) => handler = result);
        // 等 Promise resolve
        const url = await waitForHandler(handler);
        process.stdout.write(JSON.stringify({ id, ok: true, url }) + "\n");
    } catch (e) {
        process.stdout.write(JSON.stringify({ id, ok: false, err: e.message }) + "\n");
    }
});
```

#### A3. Python 端通过 `subprocess.Popen` + stdio JSON Lines RPC

**新文件** `companion/lx_runtime_client.py`:
```python
class LxRuntimeClient:
    def __init__(self):
        self.proc = subprocess.Popen(
            ["node", "lx_runtime/lx_runtime.js"],
            cwd=str(COMPANION_DIR),
            stdin=subprocess.PIPE, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
            bufsize=0,
        )
        self._next_id = 0
        self._lock = threading.Lock()

    def call(self, action: str, source: str, info: dict, timeout=10):
        """action: musicUrl/search/lyric"""
        req_id = str(self._next_id); self._next_id += 1
        req = json.dumps({"id": req_id, "action": action, "source": source, "info": info})
        with self._lock:
            self.proc.stdin.write(req.encode() + b"\n")
            self.proc.stdin.flush()
            # 读 response
            line = self.proc.stdout.readline().decode()
            return json.loads(line)
```

#### C4. 歌词显示(M3.28 Phase 5,本轮做)

##### 调研结论(2026-09-18)
受好评方案:Apple Music Big Lyrics(逐字 + 专辑色) / 网易云卡拉OK(中文强) / Spotify Musixmatch(逐行)/ Karacookie(macOS OSS,Apple 仿照)。共识:
- **逐字高亮优先**(LRCLib 70% 英文覆盖),**降级逐行滚动**
- 专辑色取主色 → 歌词高亮色
- 自动滚动保持 active line 居中
- 时延 < 200ms,允许 agent 调(默认 0)

##### 设计原则:**不做设置页面,只做显示 UI**
- ❌ 不做"调时延""调字号""调颜色""切逐字/逐行模式" UI 开关
- ✅ agent 通过 `/api/music/agent_opinion` 调:
  - `lyrics_delay_ms: int`(±10000,默认 0)
  - `lyrics_mode: "word"|"line"`(默认 `word`,源不支持降级到 `line`)
  - `lyrics_visible: bool`(默认 true,agent 可隐藏)
- ✅ 用户用自然语言告诉 LLM 「歌词快 0.5 秒」「切逐行模式」「隐藏歌词」 → PrisirAI 调 `/api/music/agent_opinion`

##### 视觉规范(参考 Apple Music + 网易云融合)
- 歌词层 z-index 1100(在音乐控制条之上),固定底部 1/3 高度
- 当前行:`color: var(--accent)`,字号 1.5em,bounce 动画 1.0 → 1.05 → 1.0
- 当前字(逐字模式):`background: linear-gradient(90deg, var(--accent) 0%, var(--accent) ${progress}%, var(--text-dim) ${progress}%)`, `background-clip: text; -webkit-text-fill-color: transparent`
- 其他行:`color: var(--text-dim)`,字号 1.2em,opacity 0.5
- 行间距 0.8em,自动滚动到当前行居中
- 背景:`backdrop-filter: blur(8px)`,在控制条之上不抢眼

##### 数据流
```
lrc 源 (lx source lyric action → LRC 字符串)
  ↓
companion 后端 lyric_loader.py 解析 LRC → [{time_ms, text, words:[{time_ms, text}]}]
  ↓
WS event "lyrics" 推送 {lines: [...], accent_color: "#hex"}
  ↓
前端 lyrics.js 渲染 → requestAnimationFrame 同步 progress
```

## 风险与回滚

| 风险 | 缓解 |
|---|---|
| LX source 失效(API 挂/解析失败) | 梯队自动切下一源 + 5 源失败才报用户 |
| jsdom 全局污染 | 子进程隔离,挂掉不污染 companion |

| Node 子进程挂掉 | companion 自动重启 + 失败提示 |
| 推荐池被封 IP | 走 m3u8 公开榜(网易云排行榜 / QQ 热歌) |
| 用户被通知中心卡骚扰 | 默认不弹,设置开关 |
| 模型乱调音乐工具 | tool schema description 严格 + system 提示「用户没要音乐不要主动调」 |
